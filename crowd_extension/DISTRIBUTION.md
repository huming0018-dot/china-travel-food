# 发一个链接，按设备安装

正式发布后，邀请人只需要复制一条短信或保存二维码，发给参与者。参与者打开同一个入口，系统识别设备，显示以下三步：

1. 安装客户端。安卓打开下载的 APK，按系统提示确认；Windows 打开普通安装程序，自动安装到当前用户并创建桌面/开始菜单图标。
2. 回到邀请页，点“已安装，继续参与”。系统询问时，选择打开众包采集。
3. 在客户端勾选自愿参与，点同意并开始，首次按提示登录小红书。随后自动领任务、搜索、采集和回传，随时可停止。

参与者不用 Git、终端、服务器地址或中台邮箱。系统的安装确认、平台登录和验证码仍由本人操作。微信/QQ 等内置浏览器会提示改用系统浏览器，并提供复制完整邀请链接的按钮。设备识别不正确时可以切换；兼容安卓的华为选择安卓，原生鸿蒙走正式鸿蒙渠道。

## 邀请人怎么发

首次部署完成会生成 `.crowd-launch/发给朋友.html`、`invite-sms.txt`、`invite-qr.png`。打开“发给朋友.html”，点“复制整条短信”，粘贴发送即可；这个页面只包含公开邀请资料，不包含部署密钥。名额和有效期仍由服务端控制。

后续可在网站 `/crowd/admin` 使用发布身份生成新的一批，点“复制整条短信”或“用短信发送”，也可保存二维码。页面只列出已开放的设备。发布身份只用于邀请管理，不能发给参与者。

## 给部署负责人

源码与原生资源：`python3 cloud/crowd_build.py`。Windows runtime：`python3 cloud/crowd_desktop_build.py --platform win32 --arch x64`。普通安装程序：`python3 cloud/crowd_windows_installer.py --arch x64`（NSIS 3，可用 `CROWD_MAKENSIS` 指定编译器）。

Windows 清单使用 desktop channel，URL 为本站 `/crowd/releases/crowd-windows-x64-v4.0.0-setup.exe`，填写实际 SHA256，设备验收通过后再标记 verified。保留旁边的 `.exe.build.json` 本地构建记录；发布检查绑定 EXE 摘要、当前公开配置、共享资源与原生源码，拒绝过期或缺构建记录的安装程序。记录不是签名或设备验收的替代。

网站仍复用现有项目。2026-10-07 已新增部署 `crowd-access`，网页通过公开项目配置调用受邀请/发布身份保护的接入接口，不再必须向 Vercel 注入网关或管理员密钥。发布者独立口令保留在私有 `.crowd-launch/operator-key`，只用于管理页面、任务发布和证据导出；不能放进参与链接或客户端。已有私有网关/直连模式继续兼容。正式网页发布可通过已连接的 Git 自动构建；安装渠道仍必须完成实机验收，不能因构建成功直接开放。三条真实店铺试点任务已发布，未创建参与者或生产证据。数据位置及尚未开启的 Docker 入库流水线见 [DATA_RECOVERY.md](DATA_RECOVERY.md)。

常规安装包过大时自动分片，邀请页自动重组并校验后下载成一个安装文件；参与者无需拼分片。网页的下载校验失败时会保留重试按钮，未就绪的入口会拒绝安装/发布。系统拦截安装包时联系邀请人核对签名，不要求参与者关闭安全保护。
