**代码层排查**：
| 排查点 | 现状 | 判定 |
|---|---|---|
| 空响应当成功 | progress_broadcast v2 实时从库计数（非静态文件） | ✅ 已修 |
| 心跳正文冻结 | v2 加"近 Xmin +Δ"趋势 | ✅ 已修 |
| 停滞静默 | v2 停滞检测→notifier.action 有界提醒→恢复 resolve | ✅ 已修 |
| 回流数据无跟踪 | **crowd_proofs 回传后无产出视角（哪些任务在推进/参与者是否活跃/去重率/拒收率分布）** | 🔴 **本轮新增 tracking 报告** |

### 2. 通知刷屏 / 打扰
**历史事故**：10 分钟播报绕过冷却、飞书监控反复推 -100 无效打扰、TG 推送无统筹。

**代码层排查**：
| 排查点 | 现状 | 判定 |
|---|---|---|
| CLI 入口绕过节流 | notifier 唯一出口，info/warn/action/resolve 全部过账本冷却 | ✅ 已修 |

| tracking 报告推送 | **无此能力** | 🔴 新增（复用 notifier.info，默认 cadence 避免刷屏） |

**排查点**：crowd_ingest 幂等键+去重唯一索引兜底 ✅；账本写入 except 静默 🟡（低风险）。

**排查点**：crowd_ingest `_fmt_ewkt` 统一转 EWKT ✅；vendor common 有坐标转换 ✅。

## 结论

- 大多数历史坑已在前几轮修复（虚假成功/通知刷屏/冻结播报）
- **本轮真正的空白 = 回流 tracking 报告**：参与者回传后，PM/用户看不到
  - 任务池推进（open→fulfilled 速率、剩余缺口）
  - 参与者活跃（谁在采、日回传量、有效/拒收）
  - 数据质量（去重命中率、拒收原因分布、评分锚定失败率）
  - 配额消耗（每日 accepted vs quota）
- 实现方式：读库聚合（crowd_proofs/crowd_participants/crowd_tasks）→ 生成人类可读报告 → 落盘 JSONL（可回溯）→ notifier.info 推送（柔和、不刷屏）
