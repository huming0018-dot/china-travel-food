# 三类来源架构与互相校准（Source Classes & Calibration）

> 上位契约：`north-star-constitution.md`、`mechanism-master-v4.md`。本文是「**数据从哪来、各源能主张什么、如何互相校准后才进事实表**」的单一真相。
> 配套：`llm-sourcing-fleet.md`（模型舰队调用细节）、`fact-claim-verification.md`（事实层）、`data-pipeline.md`（写库管线）。
> 一句话：**模型舰队负责“想得广”，UGC 负责“吃得准”，开放平台负责“对得上”；任何单源都不能直接定事实。**

---

## 1. 三类来源（角色 / 输出 / 边界）

| | ① 模型舰队 HAE | ② UGC 真实食客 | ③ 开放平台 |
|---|---|---|---|
| **角色** | 广度假设 / 自由联想生成器（L0.5 假设层） | 口味一手证据（堂食） | 跨平台佐证 + KOL 内容镜像 + 权威事实 |
| **典型源** | 豆包/Kimi/DeepSeek/Qwen/GLM/MiniMax/混元（API + 网页会员） | 小红书堂食笔记、点评长评（去软广后） | B站、抖音、公众号（搜狗微信）、微博、知乎、米其林/黑珍珠官方、地图 POI、官网、GitHub |
| **产出** | 候选实体、候选关系、跨模型共识、扩散种子 | 真实食客堂食引文、口味/菜品/人均信号 | 跨平台同内容、官方/权威事实、第二独立声音 |
| **写入位置** | **只写 `lead_hypotheses`**（物理隔离） | 经闸写 `reviews` / 口味证据 | 镜像写 `food_kol_posts/mentions`；权威事实经闸写事实表 |
| **访问门控** | API key 或网页会员（不硬买） | 平台门控最强（XHS 易限流/风控） | 相对开放、门控低（L0/L1/L2 优先） |
| **主要噪声** | 幻觉、聚合门户引用、广而浅 | 软广/刷评/硬广、分店歧义 | 同内容多平台重复、营销号镜像 |
| **默认置信** | 低（仅先验） | 高（独立食客、堂食） | 视源而定：官方/权威高，转载/镜像低 |
| **能定什么** | **不能直接定任何事实** | 可定口味（taste/diner） | 可佐证 / 可定权威事实（官方源） |

**硬边界**：
- 模型输出**绝不直写事实表**；模型自标 知道/推断/不知道，无记忆留空（宁空不假），禁止编造名字/年份/原话。
- UGC 必须是**真实食客、堂食、含具体单品**，且经去软广；商家/场地号、纯营销文案不计口味证据。
- 开放平台的**转载/镜像不新增独立声音**；只有原始权威源（官网/官方公众号/工商/原始新闻/米其林黑珍珠官方）才能定权威事实。

## 2. 校准闭环（从提议到事实）

```
①模型舰队 --fleet-recall
   自由联想/扩散 → 结构化假设（status=hypothesized）只进 lead_hypotheses
        │  每条带 confirm_queries[] + falsify_queries[]
        ▼
②③取证（UGC + 开放平台，确定性连接器，不重造）
   正向取证 + 【强制】反向证伪（关店/离职/辟谣/难吃/预制）
   联网结果必带 source_url；聚合门户只作线索
        ▼
admission gate（三条件同时满足）
   ≥2 个相互独立来源声音（不同平台/作者；同平台多帖、跨平台同内容不算）
   + 堂食口味均分 ≥3.5
   + ≥1 含招牌菜/具体单品的堂食证据
        ▼
   达标 → confirmed → --promote 确定性晋升事实表（幂等+回读），并成为新种子
   分歧/证伪 → contradicted（留痕，不晋升）
   证据不足 → unverified / hypothesized（留假设账本，不空不假）
        ▼
多轮跑到无新确认边 / frontier 清空 = 饱和收敛
```

**关系/沿革类的取证口径**（区别于口味）：
- 事实（在营/招牌/地址）= 权威源，或 ≥2 独立声音；
- 沿革/持股/师承/任职 = ≥1 可信文档（官方/新闻/工商），且页内**明确写出该职务/关系**；
- 每条假设**必须有证伪查询**，无 URL 不作证实。

## 3. 跨源处理规则

1. **同一 KOL 跨平台身份归一**：以 `food_kol_watchlist` 为主实体，把同一博主在 XHS/B站/抖音/公众号/微博/知乎/YouTube 的账号挂为跨平台 handle；博主通常跨平台同发。
2. **跨平台同内容去重**：同款文案/视频跨平台只算 **1 个独立声音**；按内容指纹（标题/正文 hash、视频 bvid/aweme 对应）去重，独立声音按“平台+作者”独立性计数。
3. **跨源分歧**：同主体出现互斥主张（在营 vs 关店、任职 vs 离职）→ 标 `contradicted`，以原始权威源裁决，裁决前不晋升。
4. **KOL 推荐只作线索**：KOL/博主/明星/作家到访、综艺（一饭封神/黑白厨房）等只作特征 tag / 发现信号，**不回写 score_***；真实口味为唯一评定（A1）。
5. **置信度按来源独立性分级**：

| 级 | 条件 | 用途 |
|---|---|---|
| C4 权威 | 原始官方/工商/米其林黑珍珠官方，页内明示 | 可直接定权威事实 |
| C3 多源 | ≥2 独立声音一致 + 堂食含单品 | 可定口味/收录 |
| C2 单源 | 仅 1 个可信声音 | 留候选、继续取证 |
| C1 假设 | 仅模型/聚合门户 | 只进 lead_hypotheses |
| C0 无据 | 无来源/记忆 | 不写（宁空不假） |

## 4. 节奏（详见各模块；账号未恢复前不依赖 XHS）

- **模型舰队**：以「菜系×场景×食材×口碑」四轴网格叶子为种子，轮转切片跑 `--fleet-recall→--prove→--promote`；每日 1–2 次、错峰低峰，N 天扫完全网格，断点幂等，限流自动退避。
- **KOL 跨平台采集**：走开放平台（B站/公众号/微博/知乎，抖音可采则采），频率可高于舰队、以去重后增量为准；新提及店过 admission gate 才入库。
- **UGC 长跑**：账号健康时单/多账号串行（per-account flock），无可用账号即安静跳过、不空转。
