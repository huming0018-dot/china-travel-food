# 出餐方式二次校验（Production Model Verification）· 升级方案

> 目标：二次校验不再只回答"是不是连锁"，而是用可复现证据链分辨
> ① 真实连锁经营 ② 商业化预制经营 ③ 资本化 ④ 大型连锁，以及 ⑤ **出餐方式**（菜怎么做到盘里）。
> 世界观：真实好吃为最高原则。**连锁本身不等于难吃；预制/复热系统性压低口味上限，才是守门员重点。**

## 1. 两个正交维度（核心解耦）

| 维度 | 字段 | 取值 | 回答的问题 |
|---|---|---|---|
| 所有权/资本 | `chain_type` | 独立店 / 小型连锁 / 大型连锁 / 资本化连锁 | 谁拥有、是否融资上市、多少店 |
| 出餐方式 | `production_model`（025 新增） | 现炒现做 / 门店现制·标准化 / 中央厨房·门店加工 / 中央厨房·门店复热 / 预制料理包·复热 / 外购成品·无堂食厨房 | 菜在哪做、做到几分、门店做什么 |

为什么解耦：大型连锁也可能每店现炒（火锅/现炒），单店也可能用料理包；
"有分店/有佐餐酒/用了某食材"都不是出餐方式证据。`production_model` 为 NULL=证据不足，**不猜**。

## 2. 证据类与信号（决定 sourcing 覆盖）

**reg（工商/许可，权重最高）**
- 食品经营许可证·经营项目：`热食类食品制售`（可现炒）/ 冷食·生食·糕点·自制饮品制售 /
  `中央厨房`（专门许可项）/ `预包装食品销售·散装食品销售`（只卖不做）。
- `SC 食品生产许可证`（工厂主体）、中央厨房许可证。
- 关联实体：同一法人/股东名下的 食品生产 / 供应链 / 净菜 / 农业 / 央厨 公司及其经营范围。
- 上市(A/H/美股)/挂牌/VC·PE 股权融资（→ 资本化）。

**branch（规模/门店）**：门店数（高德/官网/点评）、直营 vs 加盟、官网门店列表/招商加盟页。

**news（公告/媒体/招聘）**
- 年报/招股书（权威）：央厨数量、供应链、"成品/半成品配送、门店复热"表述。
- 媒体：中央厨房/工厂/供应链/料理包/复热 ↔ 明厨亮灶/现炒/明档。
- 招标采购（采购料理包/净菜）；招聘（央厨切配/包菜/食品厂工人 ↔ 门店炒锅/厨师/面点师）。
- 纪录片/网综/官方视频里的厨房形态。

**ugc（食客，多店交叉）**
- 复热：上菜极快、像加热的、料理包、预制、微波炉、无锅气、跨分店味道完全一致。
- 现做：明厨/明档可见、锅气·镬气、现炒/现包/现擀/现切、等餐久。

## 3. LLM 抽取（只进线索层，绝不直写事实表）

对每个品牌，LLM（ARK/豆包，联网）汇总证据，输出结构化信号（每条引文必带 `source_url`）：

```json
{
 "brand": "", "rids": [],
 "license_hot_cook": true,            // 热食类制售许可
 "license_packaged_only": null,       // 仅预包装/散装销售
 "central_kitchen_license": null,     // 央厨许可
 "factory_sc": null,                  // SC 工厂
 "supply_chain_entity": [],           // {entity, relation, url}
 "central_delivery_evidence": [],     // {quote, url, kind}
 "reheat_evidence": [],               // 成品配送/复热
 "premade_packet_evidence": [],       // 料理包
 "fresh_wok_evidence": [],            // 现炒/锅气/明档
 "onsite_prep_evidence": [],          // 现烤/现切/现擀
 "direct_franchise": "直营|加盟|混合|未知",
 "financing": "上市|VC融资|无|未知",
 "n_locations": null,
 "production_guess": "", "confidence": 0.0
}
```

LLM 产出先落 staging（`lead_hypotheses` / 生产探针 jsonl），由确定性 gate 映射；**LLM 不写 production_model**。

## 4. 确定性仲裁（gate，按序首匹配；独立源 n_ind=max(不同域名数, 不同证据类数)）

1. **料理包**：premade_packet n_ind≥2（或 1 个 reg SC/许可 + 任意 1 源）→ `预制料理包·复热`，premade_risk=高；
   仅 1 news/ugc → premade_risk=疑似、production_model 暂 NULL。
2. **中央厨房**：reg 央厨许可/SC/关联供应链（权威）或 n_ind≥2 → central_kitchen=确认；
   - 门店有 `热食类制售` 且有现炒/加工证据 → `中央厨房·门店加工`；
   - 成品配送/复热证据且无现炒 → `中央厨房·门店复热`；
   - 仅 1 news/ugc → central_kitchen=疑似、production_model 暂 NULL。
3. **现做**：无确认 ck/料包，且 fresh_wok（≥1 reg 热食制售 或 ≥2 ugc/news）→ `现炒现做`；
   只有现烤/现切/现擀等门店现制、流程标准化 → `门店现制·标准化`。
4. 仅预包装/散装销售许可、无热食制售 → `外购成品·无堂食厨房`。
5. 证据冲突/不足 → production_model NULL，信号进 reverify（宁空不假）。
6. financing=上市/VC·PE → `chain_type=资本化连锁`（喂给品牌归一器，优先级最高）。

## 5. 与评分 / 精选 / 前端联动

- 生成列 `is_reheat_served`（复热/料包/外购三类为真；NULL 与现做均为假，**不因未知误杀**）。
- 复热/料包：不进"必吃/值得"，口味分设上限并打"复热出餐"角标；现炒高口碑正常排名。
- 前端：新增"出餐方式"筛选/角标，"只看现做"；连锁与出餐方式解耦显示。
- **连锁本身不下架**；仅 status=closed / central_kitchen=确认且复热 / premade=高 / 食安硬证据才降或下。

## 6. 运行节奏（cron，经配额仲裁）

- 增量（每日）：新收录/变动店做探针。
- 全量（每周/月）：搜索矩阵对全品牌轻量复探，重点=已标复热/料包 与 NULL 的高价值店。
- 触发（即时）：年报/公告/食安新闻/主厨变动。
- reg 高优先、命中缓存不重复；LLM 联网调用受预算约束。

## 7. 验收 DoD

- 校准集（已知复热 vs 现炒品牌）判定全部正确、证据可复现；
- 每个非 NULL production_model 在 findings 可复现证据链；
- 复热/料包 is_reheat_served=t 且评分/精选联动，现炒独立店零误杀；
- 宁空不假、不改非目标字段。
