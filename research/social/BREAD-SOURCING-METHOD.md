# 面包线「怎么搜 · 怎么收」方法论（待你确认后回滚所有菜系）

> 目标：榜单只收**真正好吃、食客口碑出色**的店，而不是"爬虫抓到就能进"。
> 本文是把日料 demo 的方法补成**确定性代码**后的第一版，先在面包这一条线跑通，请你确认；确认后同一套机制回滚到全部菜系。

## 一、先看清旧机制为什么会"劣币驱逐良币"

抽查面包根标签下 34 家店：**33 家 review_count=0（没有一条真实食客评论），却都带着 65–85 的"口味分/食客分"**。

根因有四层：

1. **绕过了质量门批量入库**：管线本有硬门槛（≥2 条带 URL 的真实食客堂食原话、含具体菜品、≥2 独立来源），但历史一批店没经过它就进了库。
2. **供给侧视角、按店名/关键词抓地图**：平台 SEO 强、开店久、营销多的连锁/网红（SunFlour、苹果花园）一抓就进；靠口碑、SEO 弱的社区宝藏（Proust、Flour Time、Orenda、Over）搜不到。
3. **采集器只会"按已知店名取证"，不会"开放式发现"**，也没把**评论区**当作挖店来源。
4. **分数是模型/管线主观填的**，没有真实 UGC 证据，等于"伪造食客分"。

一句话：旧流程是"**先抓到谁 → 谁就进 → 再给它编个分**"；正确流程应反过来——"**先听食客在夸谁 → 取证 → 够门槛才进 → 分数由真实评价算**"。

## 二、怎么搜（从"供给侧抓店"改为"需求侧听食客声音"）

不搜店名，改搜"**食客最近在讨论、回购、私藏哪些面包店**"。分三步，全部确定性、可复跑、断点续跑：

### 步骤 1 · 语义发现词矩阵（10 组词，每词深读高互动笔记）

| 维度 | 发现词（直接用于检索，已含"上海"） |
|---|---|
| 口碑私藏 | 面包店 私藏 回购 舍不得公开 |
| 子品类·酸种 | 酸种面包 推荐 好吃 |
| 子品类·起酥 | 可颂 起酥 天花板 层次 |
| 子品类·贝果 | 贝果 好吃 推荐 口感 |
| 合集红黑榜 | 面包 红黑榜 合集 盘点 |
| 社区本地 | 社区面包店 本地人 常买 |
| 子品类·欧包 | 欧包 乡村面包 全麦 |
| 子品类·日式 | 日式面包 生吐司 推荐 |
| 反向排雷 | 面包 无广 真实测评 踩雷 |
| 跨语 | best bakery / sourdough |

> 每个菜系都会照此生成自己的语义矩阵（老饕私藏 / 子品类垂直 / 社区本地 / 合集红黑榜 / 反向排雷 / 跨语），**子品类有多少就铺多少**（面包铺了酸种·可颂·贝果·欧包·日式，拉面会铺豚骨·酱油·味噌·蘸面·荞麦·乌冬……）。

### 步骤 2 · 进笔记通读评论区（评论区是二级来源）

- 不只采正文：进每篇高赞笔记，**通读评论区**。本地人常在评论里说"另一家更好 / 真正好吃的是 XX / 本地人只买 XX"，把这些提及的店登记为**新线索**，二次溯源。
- 合集帖结构化提取：合集写法极规律（`-店名：招牌+口感`、`📍店名`、`店名丨菜品`、编号/图X），用结构化锚点提取，避免把英文名切碎。
- 品牌异写归一：`over / atelier over / L'Atelier Over Bakery` 归到同一品牌；解决 token 顺序（你说的 "Time & Flour" 实际品牌是 **Flour Time**）。

### 步骤 3 · 未知专名线索 → 锚定取证

- 对不在品牌词典/库里的新名字（如 Orenda Bay），先作为**线索**（记提及频次与语境），**不直接收录**；
- 再"按店名"定向取证（搜该店、读专门笔记与评论），证据够才收录。
- 平台以小红书为主，后续叠加抖音、B站、公众号（`site:mp.weixin.qq.com`）；视频号无公开网页，采不到如实标缺口。

## 三、怎么收（收录门槛 admission gate，宁空不假）

一家店必须**同时**满足才收录（全由脚本判定，模型只给证据、不直接写库）：

| 门槛 | 标准 |
|---|---|
| **主营判定** | 主营该品类（在合集该品类分类下 / 挂该品类标签 / 招牌单品 ≥1）；菜单里"含有"的单品不算 |
| **独立声音 ≥2** | 合集整理者（按作者去重）+ 独立食客（按评论者）合计 ≥2；且要么有 ≥1 独立食客、要么来自 ≥2 个不同整理者——**单一博主合集不算数** |
| **招牌/口感证据 ≥1** | 至少 1 处描述到具体单品或口感（可颂层次、酸种风味、贝果嚼感…），纯情绪空话不计 |
| **口味均分 ≥3.5** | 对所有有效声音做口味情感打分（1–5）取均值；<3.3 直接淘汰 |
| **差评交叉** | 有正有负、经核验 → `admit`；**全好评无差评交叉 → `admit*`（置信度下调，需补取证）** |

裁决三档：
- **admit / admit\***：够格收录（admit*=全好评、置信略低）。
- **hold**：有声音但证据不足（单一博主、无独立食客、招牌/均分不够），继续取证，不进精选。
- **reject**：已关店 / 口味均分<3.3 / 非主营该品类（跨品类噪声）。

**存量店怎么处理（SunFlour、苹果花园这类）**：不直接删除（避免误杀），但——
- 旧主观分一律不采信；库内 `review_count=0` 且本轮扫描也补不到独立食客声音的，**从"精选/推荐位"降级隐藏**，进入"待取证"；
- 给一个取证窗口，窗口内补到 ≥2 独立食客声音且均分达标可恢复，否则长期下沉。
- 电话/坐标/评论全程**宁空不假**，绝不用同名他店或错分店号码。
