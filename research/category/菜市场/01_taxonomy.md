> 用法：按 category-bootstrap.md Step2 填写。主维度单一归根，正交维度可多挂。
> 本品类为非餐饮新品类，**不写 restaurants/cuisines 表**，用独立 POI 账本承载。

## 1. 主维度（品类树）

- **一级根**：菜市场（Wet Market，独立 POI 域，虚拟根）
- **二级（经营形态）**：
  - 一级批发市场（批发，非零售散客）
  - 标准化农贸市场（零售主力）
  - 社区便民菜店/邻里荟（小而近）
  - 网红改造市集（装修/打卡向）
  - 限时早市
- **三级（主营特色，挂在零售/农贸下）**：
  - 综合型 / 水产海鲜特色 / 蔬果特色 / 肉禽特色 / 豆制品熟食特色 / 花鸟特产

## 2. 正交维度（可多挂）

| 维度 | 叶子/取值 | 挂法 |
|---|---|---|
| 区位 | 16 区 + 商圈 | 单挂 |
| 运营方 | 公立标准化 / 浦商国企连锁 / 民营承包 / 网红改造 | 单挂 |
| 特色摊位 | 活鲜水产 / 现制豆制品 / 熟食爆鱼 / 早点四大金刚 / 平价保供 | 可多挂 |

## 3. 挂法与互斥规则

- **主营 vs 含有**：形态叶按市场主体业态定（批发/零售互斥）；特色标签按"该品类摊位是否成规模、
  是否值得专程"定——个别摊位不挂特色叶。
- **互斥规则**：一级批发 ⊥ 社区零售；网红改造 ⊥ 公立平价（同一市场按主运营方单挂）。
- **名称陷阱**：
  - "菜场/市集/邻里荟/生鲜"不一定是菜市场（盒马、朴朴、超市生鲜区不算）；
  - "美食城/食集"若以档口餐饮为主（如中广食集）需人工判定是菜场还是美食广场；
  - 同名近址（如"浦商"系列是国企连锁多店，按门店地址分别建 POI）。
- **成对删挂**：市场歇业/重启在账本标 status，不物理删除（留历史）。

## 4. 命名规范

- 正名以市商务委名单/地图 POI 官方名为准；别名（如三角地、浦商系列门店后缀）入 aliases。
- 新店/新发现先入 frontier 账本，过 ≥2 独立声音再进主账本。

## 5. 数据库承载

- 主表（泛化 POI）：**独立账本** `research/category/菜市场/market_ledger.json`（本阶段），
  后续可迁到独立 `venues` 表；**不写 restaurants 表**。
- 标签：账本内 `form` / `features` / `district` 字段（jsonb 化）。
- 品类特有字段：`address`、`coordinates`（待地图 POI 免费额度补）、`opening_hours`、
  `features`（特色摊位）、`source_url`、`frame`（F2 权威框 / F5 地图框）。
- 关键约束：name+address 唯一；coordinates 缺失允许（宁空不假）但不得编造。
