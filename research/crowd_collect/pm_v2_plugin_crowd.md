## 一、需求模型（已确认）

| 维度 | 确认内容 |
|---|---|
| 载体 | **浏览器扩展**（Chrome extension, manifest v3）分发给参与者 |
| 执行 | **全自动**：插件登录参与者自有小红书账号后自动搜索/浏览/收录 |
| 节点 | 参与者自有设备 + 自有网络/IP + 自有账号，装插件即成采集节点 |
| 登录 | 参与者用自己的小红书账号登录插件（自有账号为主） |
| 回传 | 采集结果（笔记URL+锚定信息+评分）**直接回传 Supabase** |
| 红线 | 插件内建硬限频，采集强度控制在平台风控以下 |
| 动机 | Apify成本高 + 分布式真实IP降低被卡率 + 真实口味评分增量 |

## 二、架构总览

```
参与者设备（Chrome）
└─ 众包采集插件 (manifest v3)
   ├─ 任务拉取模块 ←── GET task_queue (assignee=crowd, status=todo)
   ├─ 安全线引擎（硬编码，不可调）
   │   ├─ 日搜索≤30次 · 间隔随机60-120s · 会话≤15min
   │   ├─ 触发"访问频繁"→自动停15min
   │   └─ 一机一号硬约束
   ├─ 采集执行器（搜索词包/店铺包 → 收录笔记 + 评分）
   └─ 回传上报器 → POST Supabase（task_proof / crowd_reviews）
                          ↓
                data_gate 校验（URL有效/去重/entity_match锚定）
                          ↓
                结算表 + 信用分（有效收录条数计价）
```

## 三、插件模块职责（分派）

### collector（采集侧）— 工单 #46
1. **插件骨架**：manifest v3 + background service worker + content script
2. **安全线引擎**：硬编码限频（不可由用户/参与者调整）：
   - 日搜索 ≤30次/账号 · 动作间隔随机 60-120s
   - 单次会话 ≤15min · 每篇浏览停留 ≥30s
   - 触发"访问频繁"提示 → 自动冷却 15min
   - 一机一号（本机只允许一个采集账号实例）
3. **任务拉取**：插件启动/定时拉取 task_queue 中 assignee=crowd、status=todo 的词包+店铺包
4. **采集执行**：按词包搜索 → 收录笔记（URL+标题+正文摘要+锚定候选）→ 全自动评分（规则引擎初判）
5. **回传上报**：POST 到 Supabase（task_proof 表），带 task_id / participant_id / 采集时间戳
6. **参与协议**：插件首次启动展示《知情同意书》（采集范围/账号风险/计酬规则），同意后方可运行——开源可审计

### dev（数据侧）— 工单 #47
1. **回传校验**：对接 data_gate 增加 crowd_proof 校验分支（URL 有效性/去重/entity_match 锚定到目标店）
2. **评分入库**：crowd_reviews 表设计（store_id/score/evidence/reviewer_id/trust_level），真实口味评分落库
3. **结算表**：crowd_settlement（participant_id/有效条数/单价/应结金额/状态），对接信用分体系
4. **参与者管理**：participants 表（实名/微信绑定/信用分/账号健康状态）
5. **任务包生成**：把待采集店铺池切成 5-8 店/包发布为 crowd 工单（可复用现有 task_queue）

## 四、安全线依据（调研实证）

| 依据 | 来源 |
|---|---|
| 搜索/阅读≤60次/分 · 高风险≤3/10min · 中风险≤8/10min · 低风险≤20/10min · 触限停15min | GitHub mediause/agent-skills 实测 |
| 单账号日浏览上限约几百篇 | 社媒助手实测 |
| 2026平台"语义追踪+行为轨迹检测" + 设备关联处置 | 平台公开规则 |
| 处罚阶梯：轻度扣分→中度限功能7-30天→重度永久封+关联矩阵号 | 人人都是产品经理 |

**PM红线设计（比通用经验值更保守）**：
- 日搜索 ≤30 次/账号（通用60次/分的1/200量级，留足余量）
- 单账号日收录目标 20-50 条（覆盖目标店锚定即可，不做广度轰炸）
- 新号/低活跃号额度减半，运行7天无风控信号后逐步放开

## 五、合规与风险（PM把关，必读）

1. **参与者知情自愿有偿**（已确认）——合规底线满足
2. **插件必须开源可审计**：参与者能看到插件在采集什么、回传什么——避免"不知情节点"雷区
3. **个保法§27**：只采公开数据、入库脱敏（作者名/ID最小化）、不采集私有信息
4. **账号风险告知**：参与者自有账号可能被平台限流/封禁，须写入《参与协议》明确责任边界
5. **平台ToS**：自动化采集仍违反小红书条款，本方案降低触发概率但不消除风险——由用户知悉
