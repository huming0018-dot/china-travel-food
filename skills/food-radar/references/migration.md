## 替换策略
- 替换原 SKILL 入口与相互矛盾的参考规则，重新面向食客，而不是餐饮投资研究。
- 原预检的作者路径/固定 Chromium 版本/全工具门槛，替换为按需只读检查。
- 不再以固定关键词 YAML 绑定城市与年份，改由 plan 从真实窗口生成跨月查询。
- 点评 adapter 只抓可见明确标注字段；列表与指定详情拆开，失败状态与空结果区分。
- 增加标准库 SQLite 记录、证据/时效校验、活动生命周期、偏好/收藏/反馈、作用域和增量日志。
- 旧文档 HANDOFF/PRD、references/environment/toolchain 等不复制进生效候选，以免混入作者机器状态或旧规范；保留在只读上游快照可供对照。
- 无自动 v1 数据迁移：旧数据需显式映射和补证据，避免无依据假定闭店/价格/活动日期。

## 实现边界
Skill 使用宿主联网工具。核心脚本是本地事实账本与候选过滤，不是自动跨站爬虫或餐厅数据库。稳定 ID 去重由宿主先匹配分店和活动，程序阻止明显 ID 身份冲突，不声称完全解决模糊实体匹配。
已实现 increment log 但没有提醒投递/计划任务。口味解释由助手按证据完成，不用数字装作“最好吃”。新菜单的变化会入日志，但主动跟踪需要用户指定关注对象与订阅后接宿主调度。
真实点评登录/DOM、公众号、小红书通路未经本机端到端认证；不承诺绕过登录或每个平台一直可用。无登录也可使用公开搜索主路径。
项目根目录未确认到适用全仓库的许可证；本次仅制作本地审阅候选，未向上游提交或公开再分发。
