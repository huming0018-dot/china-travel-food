# food-radar 校验规范（Validation Spec）

## 一、三条铁律（违反即返工）

1. **双信源+日期规则**：任何"新开/在营"结论必须有两个独立信源，且两个信源都带明确的当年（当前年度）日期。仅一个信源 → `confidence` 降为 medium 并标注待核实。
2. **发布日期核对规则**：引用任何文章前必须核对并记录其发布日期；禁止凭内容语感判断新旧。搜索引擎摘要不带年份时，必须打开原文确认。
3. **在营核查规则**：上榜/获奖 ≠ 在营。每家店交付前必须做一次闭店/退出核查（检索"店名+闭店/停业/退出"），有闭店信号的一律移入 `excluded` 并注明原因。

## 二、信源冲突裁决

冲突时按级别裁决：S（官方/官媒/榜单）> A（行业媒体/KOL）> B（UGC）> C（软文）。
同级别冲突：取日期新者；仍冲突 → 两个说法都写进 `notes`，`confidence` 降一级。

## 三、数值类信息规则

- 评分、人均、榜单年份：必须记录"来源平台+抓取日期"；拿不到填 null，禁止估算。
- 米其林/黑珍珠荣誉必须带年份（如"2026米其林二星"），往年荣誉注明"往年"。

## 四、交付前 Checklist（全部通过才可交付）

- [ ] 每家店/事件都有 ≥1 个 S 或 A 级信源
- [ ] 所有 `opened_date` 来自显式日期，无猜测
- [ ] 每家店做过闭店/退出核查
- [ ] `confidence=high` 条目均满足双信源规则
- [ ] C 级软文线索未被直接引用
- [ ] 所有假设（如对标物无法确认）已在输出开头向用户声明
- [ ] 精确数值均标注来源与抓取时间，无编造

## 五、失败案例登记（持续追加）

| 日期 | 案例 | 违反规则 | 后果 |
|---|---|---|---|
| 2026-10-16 | 攏好粤菜被列为"10月新开" | 违反规则2（2024-10文章误判为2026-10）+ 规则3（未做在营核查，实际2024年已退出上海） | 用户纠正后移出推荐位，沉淀为本规范 |
