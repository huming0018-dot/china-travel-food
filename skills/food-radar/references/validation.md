## 一、四条铁律（违反即返工）

1. **证据规则（v3 修订，不再机械双信源）**：结论所需的独立信源数量**按问题类型定**（见第二节）。
   - **独立性判定**：同一通稿的多家转载**不算**两个独立信源（用 `origin_id` 去重）。
   - **证据同等时给并列选择**，不按编号硬选"最佳"。
   - 日期落在**查询时间窗**内即可；跨年查询允许往年信源，须在 notes 标注年份。
   - **采集失败 ≠ 无餐厅/已闭店**，统一 `channel_unverified`。
   - 证据不足以定论 → 相应字段 `value=null` + notes 说明，**不用"疑似/可能"填充**。
2. **发布日期核对规则**：引用任何文章前必须核对并记录其发布日期；禁止凭内容语感判断新旧。搜索引擎摘要不带年份时，必须打开原文确认。
3. **在营核查规则**：上榜/获奖 ≠ 在营。每家店交付前必须做一次闭店/退出核查（检索"店名+闭店/停业/退出"），有闭店信号的一律移入 `excluded` 并注明原因。
4. **否定结论必须有正向证据规则**：判断"没数据/被拦截/不存在"前，必须先证明采集通道本身可用（用已知存在的实体做对照实验）。禁止用"页面提示不存在"作为"数据不存在"的依据。用户/人工观察优先级高于工具结论，冲突时先查自己的假设。详见第六节。

## 二、信源冲突裁决（2026-10-17 修订：按问题类型分治，不搞一刀切）

> 原规则把 S>A>B>C 统一套用，但**营业状态、榜单荣誉、食客口味**三类问题的证据强度完全不同。

| 问题类型 | 首要证据 | 次要/不可单独采信 |
|---|---|---|
| **营业状态**（是否还开着） | S 级：官方公告、政府/官媒、门店自有渠道 | B 级 UGC 只能作为"闭店线索"，不能单独定性 |
| **榜单荣誉**（米其林/黑珍珠/必吃榜） | S 级：榜单官网/官方发布 | 媒体报道、UGC 转述一律不作为荣誉依据 |
| **食客口碑**（好不好吃、值不值） | B 级：多平台 UGC 交叉（≥2 个平台） | A 级媒体稿是**商业软文**，不能作为口碑依据 |
| **开业时间** | S/A 级且带明确发布日期 | 搜索摘要不带年份时必须开原文 |

**同级别冲突**：取日期新者；仍冲突 → 两个说法都写 `notes`，`confidence` 降一级。

## 三、数值类信息规则

冲突时按级别裁决：S（官方/官媒/榜单）> A（行业媒体/KOL）> B（UGC）> C（软文）。
同级别冲突：取日期新者；仍冲突 → 两个说法都写进 `notes`，`confidence` 降一级。

## 三、数值类信息规则

- 评分、人均、榜单年份：必须记录"来源平台+抓取日期"；拿不到填 null，禁止估算。
- 米其林/黑珍珠荣誉必须带年份（如"2026米其林二星"），往年荣誉注明"往年"。

## 四、交付前 Checklist（全部通过才可交付）

- [ ] 每家店/事件都有 ≥1 个 S 或 A 级信源
- [ ] 所有 `opened_date` 来自显式日期，无猜测
- [ ] 每家店做过闭店/退出核查
- [ ] `confidence=high` 条目均满足**该问题类型所需的**独立证据量（见第二节，非机械双信源）
- [ ] C 级软文线索未被直接引用
- [ ] 所有假设（如对标物无法确认）已在输出开头向用户声明
- [ ] 精确数值均标注来源与抓取时间，无编造

## 六、否定结论规范（2026-10-17 新增，代价最大的一条）

**背景**：点评采集连续 8 轮失败后，我得出"自动化不可行，降级页阻断了搜索"的结论，并建议用户接受放弃。
用户当即反问：**"我能在页面里看到当霁，你却拿不到数据。"**

**根因**：我用 `.no-result` 元素（文案"商户没有被收录？添加商户"）作为"无结果"的判据，
**而该元素永远存在于 DOM 中**。于是**有结果的页面被判成无结果**，进而推出"被降级阻断"的错误结论。

### 铁律 4：否定结论必须有正向证据

- **禁止**用"页面提示不存在"作为"数据不存在"的依据
- **必须**用**目标内容的正向存在**判定成功（如"搜到了 `a[href*='/shop/']` 链接"）
- 下"没有找到"这类结论前，必须先证明**采集通道本身是通的**（用已知存在的实体做对照实验）

### 当用户/人工观察与工具结论冲突时，先信观察

人在页面上看到的内容是**优先级最高的证据**。此时正确动作是**回头查自己的假设**，
而不是解释对方看错了。

> 本次若用户未质疑，我会把一条**可用**通路永久标记为"不可用"，并连带影响后续所有依赖点评的任务。
> 换掉一个失效选择器（`div.shop-wrap` → `a[href*='/shop/']`）后，第一次就通了。

## 七、工程判据速查（2026-10-17 沉淀）

| 判据 | 正解 | 常见误判 |
|---|---|---|
| 第三方爬虫是否可用 | 先 curl 其核心接口看返回码 | 先装环境再发现接口已死 |
| 登录态是否成功 | cookie 非空 **且** 有数据落盘 | 凭"显示已登录"或用户口述 |
| 搜索是否有结果 | 目标链接/节点**存在** | 看"无结果提示"元素在不在 |
| 抖音签名失败 | 先确认 execjs 运行时（Node） | 按报错字面去装 Java |
| 页面文本是否完整 | 对比截图 / `innerText` 长度 | 信任 `innerText` 前段 |
| headless 是否可用 | 与 headful 实测对比 | 默认无头可用 |
| 同一方案连续失败 | 第 2 次即换方向 | 在同一路径上反复微调 |
