# food-radar 检索 Checklist

> 按阶段勾选，全部通过方可交付。depth=quick 时可跳过标注 [deep] 的项。

## 阶段一：准备（5分钟）

- [ ] 确认城市、时间窗、品类范围
- [ ] 对标物解码完成；无法确认的对标物已向用户声明假设
- [ ] 运行时检查：node -v（微信检索）、python3（MediaCrawler）、agent-browser 可用性
- [ ] 关键词矩阵已生成（≥6组，覆盖时间词×事件词×品类词）

## 阶段二：检索（standard 至少3通路）

- [ ] web_search × ≥8 组查询，覆盖官媒/政府号/行业媒体
- [ ] 对高价值页面用 web_fetch 读原文（记录发布日期）
- [ ] wechat-article-search × ≥2 组关键词（叠加时间词，只取当年结果）
- [ ] [deep] agent-reach / media-crawler 搜小红书、抖音、B站、微博
- [ ] [deep] agent-browser 抓大众点评店铺页（评分/人均/在营状态）
- [ ] 榜单核查：米其林/黑珍珠/必吃榜当年榜单涉及店逐一记录

## 阶段三：校验（铁律）

- [ ] 每条候选：开业/事件日期来自显式日期的 S/A 信源
- [ ] 每条候选：≥2 独立信源（high 置信）或已降级标注
- [ ] 每家店：闭店/停业/退出核查已完成
- [ ] 精确数值（评分/人均/榜单年份）：来源+抓取时间已标注，无编造
- [ ] C 级软文线索未被直接引用

## 阶段四：输出

- [ ] JSON 按 field-spec.md（必填字段齐全、枚举正确、日期 ISO 格式）
- [ ] 人类可读摘要：分"新开店"与"联弹/客座事件"两类，每条附口碑证据与合作切入点
- [ ] "已剔除"区列出被排除项及原因（如：2024年已退出上海）
- [ ] 假设与待确认事项已在开头显式声明

## 阶段五：沉淀

- [ ] 本次新增信源已加入 toolchain.md 信源清单
- [ ] 新踩坑已登记到 validation.md 失败案例表
- [ ] 用户口径偏好（如价位带、合作方式）已写入长期记忆
