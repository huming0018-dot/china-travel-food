# 关系图递归法（knowledge graph method）

**用途**：每完成一次预约，就把它变成关系图上的一个新节点，而不是一条孤立的日程。

**这套方法经过 2026-10 实测**：从 9 家餐厅出发，追出 6 条关系网（CIA 校友、潮上潮、Odette、泰安门、富臨/Forum、解香楼），并识破 2 个错误推断。

---

## 五步法

### 第 1 步｜锚点：固定客观事实

先只拿**可验证的店铺字段**，不碰人：

```
店名 / 地址（精确到门牌）/ 开业时间 / 菜系 / 营业时间 / 人均 / 预订方式
```

**来源优先级**：官方渠道 > 地图 POI（腾讯地图命中率高）> 媒体 > UGC

> 实测：腾讯地图 POI 是**地址与营业时间最可靠的公开源**，比点评/Trip 准确（例：WIP 建国西路485-1号、18:30-21:30 只有它给对）。

### 第 2 步｜人：找到署名主厨

**搜索模板**：
```
"<店名> 主厨"
"<店名> 行政总厨"
"<店名> 主理人 创始人"
"<店名> chef"
```

**要拿到的字段**：姓名 / 年龄或代际 / 性别 / 国籍或籍贯

**若查不到具名主厨 → 在此停止**，标注 `无具名主厨`，不要继续追（多为资本项目或连锁）。

### 第 3 步｜出身：分清三种关系

**这是最容易出错的一步。** 中文语境里"师出同门"常被滥用，必须落到三类之一：

| 类型 | 判据 | 取证关键词 |
|---|---|---|
| **校友 alumni** | 同一学校，无师徒名分 | `<人名> 毕业`、`<校名> 校友` |
| **师承 master-disciple** | 明确拜师，有"徒弟/恩师"表述 | `<人名> 拜师`、`<人名> 徒弟`、`<人名> 恩师` |
| **同事 workplace** | 同店共事，无师徒名分 | `<人名> 曾任`、`<店名> sous chef`、`<店名> 团队` |

**搜索模板**：
```
"<人名> 师承"
"<人名> 履历"
"<人名> 专访"
"<人名> 徒弟"
```

**铁律**：三种关系**不得互相替换**。校友写成师承、同事写成同门，都会污染整张图。

### 第 4 步｜网络：横向扩展

拿到一个人之后，四个方向同时探：

| 方向 | 搜索模板 | 产出 |
|---|---|---|
| **师门规模** | `"<人名> 徒弟 名单"`、`"<人名> 弟子"` | 同门名单 → 各自开店 |
| **前东家** | `"<店名> 出身"`、`"<店名> 团队 出走"` | 该店的人才输出线 |
| **联弹史** | `"<人名> 四手联弹"`、`"<店名> 联弹"` | 跨菜系连接（高频合作=地位信号） |
| **同址前身** | `"<地址> 前身"`、`"<路名> <门牌> 餐厅"` | 该铺位的历史，常揭示主厨流动 |

**实测价值**：
- 富臨的联弹史直接串出 Bombana、Roland Schuller、阮明燊三条线
- 杨贯一师门 300 人，维基列出 10 名入室弟子 → 每人背后是一家店
- Lunar（建国西路）→ Canvas 222 的接替，揭示了 Johnston Teo 的创业前史

### 第 4.5 步｜评论区挖掘（低成本高回报）

**主厨自己的笔记，评论区往往比正文信息量大。** 因为正文是官宣口径，评论区是熟人社交。

**四类高价值评论**

| 类型 | 识别特征 | 能问出什么 |
|---|---|---|
| **同行账号** | 用户名含"大厨""主厨""chef""料理人" | 位置、师承、内情（同行知道同行） |
| **老客** | 出现"以前""一别""想念""终于" | 主厨的**前一家店**或**前一道招牌菜** |
| **直接提问** | "在哪里""怎么预约""需要预约吗" | 说明该信息**尚未公开**，是缺口而非已知 |
| **作者的回复** | 主理人本人回评 | **与提问对照，能反推出未说出口的事实** |

**本次实例（WIP，2026-10）**

正文只说"离开潮1/2 之后去采风"，没说之前做过什么。评论区给出了三块拼图：

1. **老客「肚余余」**："终于！！！**牛叉烧**一别以后十分想念"
   → 说明主厨此前有一道招牌叫**牛叉烧**
2. **主理人回复**："哈哈哈哈 快来！**这次做🐷**"
   → 之前做**牛**，这次做**猪**
3. 对照 WIP 菜单：**叉烧饭（伊比利亚猪梅肉低温慢煮后炭烤）**
   → **技法延续（叉烧），主料更换（牛→猪）**

**结论**：叉烧是这位主厨的连续性技法标识。即便店换了、城市换了，招牌技法会跟人走。

4. **同行「黄馒头大厨」**："在建国西路哪里？"
   → 同行只知道街区、不知道门牌，说明**铺位信息当时还没公开**（印证我们的判断）

**操作要点**

- 评论区要**滚到底**再判断，前 10 条多为寒暄
- 优先看**作者回复了谁**——被回复的人通常是熟人
- 提问若无人回复，那条信息就是真缺口，记进"待补"
- **同一道菜在不同店重复出现，是最硬的关系证据**（比任何"师出同门"的说法都可靠）

### 第 5 步｜递归：对新节点重复 2–4

**上限两跳**：从你订的店出发 → 店 → 主厨 → 其师承/前东家。到此为止。

超过两跳会滑向与吃饭无关的行业八卦，浪费 token 且不改善订位。

## 停止条件（四条硬规则）

1. **无具名主厨** → 停
2. **连锁单店店长**（非主厨）→ 停
3. **两跳已满** → 停
4. **答不出"这对下次订位有什么用"** → 停

## 证据纪律

| 等级 | 标准 | 允许的表述 |
|---|---|---|
| `confirmed` | ≥2 个独立来源一致 | 可以下结论 |
| `partial` | 单一来源，或关键字段缺一 | 写"据 X 报道"，不下定论 |
| `unverified` | 仅 UGC 提及 | 只记录，不推断 |

**硬事实（人名、日期、师承、星级）不接受单一小红书笔记作为定论。**

**冲突处理**：并列记录，不取平均，不择优。例：潮上潮"二星/三星"两个来源冲突 → 两个都写，标注待核。

## 已识破的错误推断（案例库）

递归最容易出的两类错，都实际发生过：

### 案例 1：把校友当师承

小红书称 WIP 水主厨"和 fabula 的 chef Zee **师出同门**"。

追查发现：两人都是 **CIA 毕业**，但无任何共享师父的证据。Zee 的路径是 CIA → Le Bernardin → 泰安门 → fabula；水主厨是 CIA → 潮1/2 → WIP。

**结论：校友，不是师承。**

### 案例 2：把"曾任职"当"拜师"

WIP 笔记称水主厨"在离开**潮1/2**之后"。潮1/2 的公开主厨是张一峰与吴稚阳（师徒）。

看似能连成"水主厨 = 吴稚阳 = 张一峰徒弟"，**但吴稚阳是商科出身转行，不是 CIA 毕业**，两人不可能同一人。

**结论：水主厨是潮1/2 团队成员，不是吴稚阳，也不能归入张一峰门下。**

### 案例 3：同姓不同人

搜"水师傅"命中**文华东方中餐行政总厨水师傅**（与黄景辉搭档）。这是**另一个人**，与 WIP 水主厨无关。

**教训：中文姓氏+称谓的搜索命中，必须用机构/城市/时间交叉验证。**

## 输出格式

三种卡，全部放在 `knowledge/`：

| 类型 | 文件名 | 必填 |
|---|---|---|
| restaurant | `r-<slug>.md` | 地址、菜系、主厨、`confidence` |
| chef | `c-<slug>.md` | 现职、`lineage_type`、`master` |
| venue-network | `n-<slug>.md` | 关系类型、成员、结构图 |

**每张卡必须有 `sources` 段**，关键字段能追到具体链接。

---

## 写卡时的自检清单

- [ ] 地址是否精确到门牌？来源是否 POI/官方？
- [ ] 主厨是否有名有姓？（没有就标"无具名"）
- [ ] 师承关系标了 alumni / master-disciple / workplace 哪一类？
- [ ] 有没有把 UGC 的说法直接当结论？
- [ ] 冲突字段是否并列而非择一？
- [ ] 这张卡能不能回答"下次订位有什么用"？
