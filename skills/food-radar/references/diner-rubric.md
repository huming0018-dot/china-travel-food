# 面向资深食客，不等于面向高价餐厅
## 已知 vs 未知
用户明确说“吃过很多店，对口味、新鲜、特殊食材有要求”：可设 experience=experienced、priorities=["口味","新鲜","特殊食材"]。这只是重视维度，不代表喜欢所有猎奇食材，不代表追求昂贵/重口/生食。具体 liked_tags/avoid_tags/allergies 留空直到明确表达。过敏与不喜欢分开。
每次条件优先于长期偏好。将这次想吃辣直接扩大为永久嗜辣是错误的。反馈保留日期、分店与菜，复访理由需有新证据。

## 判断维度
1. 菜品：核心风味、酸甜苦咸鲜、油脂/口感、火候稳定性、用餐节奏。有多少证据就说多少，不用“闭眼冲”。
2. 食材：品种/部位/产地/季节/处理方式/供应稳定性。餐厅的“当天到货”是其自述；把“据店方”保留，不能宣称亲测。稀有不必然更好，普通食材的精准处理也可构成专程去的理由。
3. 新鲜度：区分食材状态、资讯发布时间、相对本人历史的新体验。成熟度、熟成、发酵与保鲜不能混淆。
4. 技法与风格：具体烹调和搭配，不能把榜单/主厨履历代替实际菜品证据。活动同样不能因客座头衔保证好吃。
5. 新意：未记录到访只是“待确认是否去过”；新菜单、当季食材和换主厨可使老店值得重访。先看本人记录，再解释新意。
6. 取舍：价格包含哪些、份量、套餐自由度、服务/环境是否符合场景。没有预算就不擅设消费层级。

## 快速 / 深查
快速：少量高相关检索，先给短名单与未知项；不要为了双信源机械拉长回答。
深查：用户选中后，再核验日期/当前菜单/供应/费用/订位。对“特殊食材必吃”使用明确 required tag；仅凭历史菜单不能保证当天供应。无法确认供应就写待门店确认。
来源冲突按事实处理，广告/合作稿标出；独立来源是采编来源独立，而不是 URL 数量。公开搜索漏检不能证明没有活动。
